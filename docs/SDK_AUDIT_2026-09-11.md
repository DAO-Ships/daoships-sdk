# SDK security, stability and efficiency review

Reviewed 2026-09-11 against the source for `0.1.0-alpha.2`. This review covers
the handwritten SDK runtime, transaction/recovery and deployment workflows, provider
compatibility, indexer/IPFS/realtime adapters, Orchard harness, generated artifact
provenance, package boundaries and release checks. It adds 12 behavioral regressions.
Earlier audit documents retain their historical observations and test counts.

## Findings fixed

| Area | Problem | Change and verification |
| --- | --- | --- |
| Navigator deployment receipts | A separate parser bypassed log/data limits, crashed on malformed neighboring logs, and labeled unknown status as reverted. Deferred ABI string errors could escape validation. | Reuse the shared event decoder, preserving emitter/identity checks. Unknown status returns `TX_PENDING`; only status zero returns `TX_REVERTED`. Regressions cover bounds, malformed logs and invalid UTF-8. |
| Transaction simulations | Chain preparation and deployment workflows accepted any successful RPC return, including malformed or oversized data. | Use the shared bounded contract-call transport. Tests reject missing, odd-length, nonhex and oversized responses while preserving the exact sender, value, calldata and block. |
| Deadlines | Provider or adapter code that blocked the event loop could return after a deadline but before its timer fired. Expired queued recovery work could start. | Check elapsed monotonic time before accepting recovery preflight, confirmation and adapter results, and before starting queued work. Tests prove no late preflight broadcast, unused nonce release and continued progress for the next queued operation. Late confirmation remains `TX_PENDING` with its hash. Active sends retain their recovery exclusion. |
| Stream consumption | Two readers retained every chunk until decoding. Tiny chunks inflated object overhead; reused buffers corrupted responses. Immediately available empty chunks could starve cancellation timers. | One shared collector copies into a geometrically growing buffer bounded by the byte limit, with periodic yields for cancellation. Tests cover reused buffers, exact size limits, oversize rejection, empty chunks, abort and timeout cleanup. |
| Indexer request isolation | A custom fetch implementation could accidentally mutate headers used by subsequent requests. | Give every request its own header object. A regression mutates the first request and verifies the next retains its schema and API key. |
| RPC nonce parsing | Arbitrarily long nonce strings reached regex/BigInt conversion before safe-integer rejection. | Reject overlong input before parsing. Safe maximum decimal, hexadecimal and numeric nonces remain supported. |

The receipt and stream changes remove duplicate implementations; simulation paths
now share existing validation. No dependency was added or upgraded. The SDK continues
to pin `quais@1.0.0-alpha.53`.

`parseNavigatorDeploymentReceipt` has an optional fourth argument with `maxLogs` and
`maxDataBytes`, matching `parseContractEvents`. Existing calls retain their signature
and now receive the shared default bounds. Error messages are diagnostic; consumers
should branch on stable SDK error codes.

The behavioral tests run through `scripts/run-tests.mjs`, so results count individual
tests rather than merely successful child test files. Generated ABI/bytecode dictionaries
are checked against compiler/source provenance instead of inflating runtime coverage.
The DAO/navigator behavior suites use MockAvatar; the separate deployment suite uses
actual QuaiVault bytecode. The [function coverage report](DAO_NAVIGATOR_FUNCTION_COVERAGE.md)
describes those fixtures and the distinction between function and adversarial coverage.

Reproduce the complete local checks with `npm run validate:workspace`. Node 22 and 24
were also run against the same compiled checkout using `node scripts/run-tests.mjs`.
The dependency snapshot used `npm audit --json --ignore-scripts`.
Live read checks used `node scripts/test-hosted-indexer.mjs testnet` and `mainnet`.
Thirteen testnet tables and seventeen mainnet tables were empty, so those checks
validate accepted projections without exercising populated row shapes. The package
check ran offline with the installed dependency graph; it did not perform a fresh
registry installation or publish an archive.

## Remaining limits

- The existing Orchard evidence covers launches, all eight activations, populated
  indexer rows and recovery. It does not exercise every business write on a public
  network. This audit adds no funded transaction or mainnet execution claim.
- Hostile-token behavior, further boundary combinations, provider diversity, live
  replacement races and reorgs remain in the [coverage backlog](DAO_NAVIGATOR_FUNCTION_COVERAGE.md).
- Caller-owned signers, persistence backends and executors remain trust boundaries.
  SDK deadlines cannot forcibly interrupt arbitrary synchronous JavaScript or revoke
  a send already in progress. Unknown sends must be reconciled; timing out is never
  permission to retry them. The file backend is disposable conformance support.
- Mainnet uses the same provider and validation, with separate network and deployment
  configuration. Captured mainnet/Orchard nonce regressions pass; confirmation depth
  and indexer freshness do not establish finality or independently attest remote data.
- Zero dependency advisories and passing coverage are evidence for this checkout,
  not an independent cryptographic or Solidity security certification.

These fixes are included in `0.1.0-alpha.2`. Operational release
gates and earlier live observations remain in [release readiness](RELEASE_READINESS.md).
